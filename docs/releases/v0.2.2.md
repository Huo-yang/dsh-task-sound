## 修复插件配置页整块消失

- 修正 bundle 组合层里的 Loader 行名：现在与包清单一致使用 `@huo-yang/dsh-task-sound`。行名与包名不相等时，DSH 的 `dsh.client` 扫描会跳过整个包，浏览器半边永远进不了 `window.__DSH_BOOT__`；Host 半边仍能加载，所以症状是「插件在跑、插件详情页没有配置」。
- 修正浏览器半边的模块 id 与 `plugins.bundle.config` 槽位锚点，同样改用 npm 包名。
- 新增守护测试：Loader 行名、客户端模块 id 与 `package.json` 包名不一致时 `pnpm test` 直接失败。
- 插件行为、通知逻辑和配置格式与 `v0.2.1` 相同；本版只修复加载与挂载。
- 使用 `dsh plugin --profile web add @huo-yang/dsh-task-sound@0.2.2` 安装。

已在 DSH `0.2.2-rc.5`、Node.js 24 和 Windows 上实际验证：插件进入客户端模块图、插件详情页正常渲染配置区（启用开关、最短任务时长、提醒范围与工作区选择、测试提醒、保存）。Windows 与 Ubuntu CI 均执行完整检查；通知投递仍仅支持 Windows。

## Fix the missing plugin settings page

- The bundle patch now mounts its Loader row by the package name `@huo-yang/dsh-task-sound`. When the row name differs from the package manifest name, DSH's `dsh.client` scan skips the package, so the browser half never enters `window.__DSH_BOOT__` while the Host half keeps loading — the plugin runs, but its settings page stays empty.
- The browser module id and the `plugins.bundle.config` slot key now use the npm package name as well.
- Added regression tests that fail in `pnpm test` when the row name, the client module id, and the npm package name drift apart.
- Plugin behavior, notification logic, and configuration format are unchanged from `v0.2.1`; this release only fixes loading and mounting.
- Install with `dsh plugin --profile web add @huo-yang/dsh-task-sound@0.2.2`.

Verified on DSH `0.2.2-rc.5`, Node.js 24, and Windows: the package joins the client module graph and the plugin detail page renders its settings section (enable switch, minimum duration, notification scope with workspace selection, test notification, save). Full checks run on Windows and Ubuntu CI; notification delivery remains Windows-only.
